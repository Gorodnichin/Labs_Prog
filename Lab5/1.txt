🔴 Критическая ошибка несоответствие сообщения об ошибке в тесте
В файле teststest_moving_average.py есть тест test_window_bigger_than_data_raises, который проверяет, что при окне больше длины ряда возникает ValueError с сообщением, содержащим подстроку больше длины.

Однако в реализации simple_moving_average (файл num_seriesmoving_average.py) используется функция check_window, которая в этом случае выбрасывает исключение с другим текстом

python
# num_seriesmoving_average.py, строки 14-15
if window  n
    raise ValueError(fwindow ({window}) не может превышать длину ряда ({n}))
Сообщение содержит «превышать длину», а не «больше длины». Поэтому тест test_window_bigger_than_data_raises упадёт с ошибкой несоответствия регулярному выражению. Это прямая ошибка, которую необходимо исправить, либо изменив сообщение в коде на «больше длины», либо скорректировав регулярное выражение в тесте.

⚠️ Дублирование и конфликтующая реализация simple_moving_average
В том же файле moving_average.py присутствуют два определения функции simple_moving_average

Первое (строки 6–10) — содержит синтаксическую и логическую ошибку переменная result используется без инициализации, что при вызове привело бы к NameError. Кроме того, в нём есть дублирующийся цикл.

Второе (строки 16–19) — корректная реализация.

Хотя в Python второе определение перезаписывает первое, наличие ошибочного дубликата — это серьёзный дефект, который может сбить с толку и привести к ошибкам при рефакторинге. Рекомендуется удалить первую (ошибочную) версию.

🟡 Особенность работы флага --json
В main.py при использовании флага --json сначала выводится JSON-представление результатов, а затем всё равно печатается полный текстовый отчёт (заголовок, статистика, ряды). Это может быть неожиданно для пользователя, ожидающего машиночитаемый вывод. Обычно при --json подразумевается только JSON.
